# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

A fork of the FreeBASIC compiler (`fbc`), upstream at https://github.com/freebasic/fbc (SourceForge is the
original home; the FB forum at https://freebasic.net/forum/ is where upstream discussion happens). The goal of
this fork is to prepare fixes and improvements to propose upstream via GitHub pull requests, so keep changes
small, self-contained, and in upstream style (see "Conventions"). `origin` is the fork
(retro778/fbc), `upstream` is freebasic/fbc. Local `master` carries fork-only commits (this file), so **cut PR
branches from `upstream/master`, not from `master`**, or the fork-only commits leak into the PR. Open PRs with
`gh pr create --repo freebasic/fbc --base master --head retro778:<branch>` (the `gh` CLI is logged in as the
fork owner), one focused branch per fix, and never push to `upstream`. Keep `master` synced with
`git fetch upstream && git merge upstream/master`.

Three components live here:

- `src/compiler/` — fbc itself, written in FreeBASIC (`.bas`/`.bi`). Building it needs a working host fbc.
- `src/rtlib/` — the runtime library (`libfb`, `libfbmt`, `fbrt0.o`), written in C with some asm.
- `src/gfxlib2/` — the graphics library (`libfbgfx`), written in C.

Plus `inc/` (FB headers for third-party libraries, mostly generated by fbfrog), `tests/` (the test suite),
`doc/` (manpage, wiki tooling), `examples/`, and `contrib/` (packaging, CI scripts, tools).

## Build

The root `makefile` builds everything into the source tree (`bin/fbc`, `lib/freebasic/<target>/` in the
default non-standalone layout, e.g. `lib/freebasic/linux-x86_64/`) so the fresh build can be tested without
installing. A full build on this machine takes a few minutes. The host compiler defaults to `fbc` on `PATH`; override with `FBC=`.
Settings can be made permanent in an untracked `config.mk` (see the makefile header for all variables).

```sh
make -j$(nproc)                 # compiler + rtlib + gfxlib2
make compiler                   # just bin/fbc (fast; most compiler work only needs this)
make rtlib gfxlib2              # just the C libraries
make clean-compiler             # force a full compiler rebuild
make FBFLAGS="-g -exx" compiler # debug compiler build (asserts, bounds/null checks, __FB_DEBUG__)
make CFLAGS="-g -Werror -DDEBUG" rtlib
make V=1 ...                    # show full command lines
```

To use the freshly built compiler, run it with `-i inc` so it finds the tree's headers:

```sh
bin/fbc -i inc examples/hello.bas
bin/fbc -i inc -gen gas64 foo.bas    # pick a backend: gas | gas64 | gcc | llvm | clang
bin/fbc -i inc -r -R foo.bas         # emit/keep the backend output (.asm/.c/.ll) for inspection
bin/fbc -i inc -pp foo.bas           # preprocessor-only output
```

CI (`contrib/travis/build-and-test.sh`) builds fbc with a release bootstrap, then rebuilds fbc with itself,
then runs the full test suite. Reproducing the self-rebuild step is a good sanity check for compiler changes:

```sh
make compiler && mv bin/fbc bin/fbc1 && make clean-compiler && make compiler FBC='bin/fbc1 -i inc'
```

## Tests

All test commands run from `tests/` with `FBC` pointing at the compiler under test (the root makefile has
wrappers `make unit-tests`, `make log-tests`, `make warning-tests` that do this for `bin/fbc`).

```sh
cd tests
FBC="$PWD/../bin/fbc -i $PWD/../inc"
make unit-tests FBC="$FBC"          # fbcunit tests -> builds and runs ./fbc-tests
make log-tests  FBC="$FBC"          # non-fbcunit tests; summary in failed-<lang>.log ("None found" = pass)
make log-tests  FBC="$FBC" FB_LANG=qb   # one dialect only: fb | fblite | qb | deprecated
make failed-tests FBC="$FBC"        # re-run only what failed last time
make clean                          # also forces a rescan for added/removed test files
```

Useful options: `DEBUG=1` (-g), `EXTRAERR=1` (-exx), `GEN=gas|gcc`, `ARCH=`, `TARGET=`,
`ENABLE_CHECK_BUGS=1` (enable tests for known-unfixed bugs), `UNITTEST_RUN_ARGS=` (passed to `./fbc-tests`,
e.g. `-v`, `--brief-summary`).

Two kinds of test, selected by a `' TEST_MODE : ...` comment in the source:

- **fbcunit tests** (`FBCUNIT_COMPATIBLE`, or any file including `fbcunit.bi`): compiled into the single
  `fbc-tests` executable. `SUITE( name )` must match `dir/filename` (checked by `check-suite-names.sh`).
- **log tests**: `COMPILE_ONLY_OK`, `COMPILE_ONLY_FAIL`, `COMPILE_AND_RUN_OK`, `COMPILE_AND_RUN_FAIL`,
  and `.bmk` multi-module tests (`MULTI_MODULE_OK/FAIL`). Each produces a `.log` beside the source.

Running a single test:

```sh
# one log test: the .log rule is per-file; the leading "./" is required because the generated
# list uses that spelling, and FB_LANG must match the test's dialect
cd tests && make -f log-tests.mk ./compound/elseif-after-else.log FB_LANG=fb FBC="$FBC"
cat compound/elseif-after-else.log        # shows TEST_MODE, fbc output, RESULT=PASSED/FAILED
# one fbcunit test: build libfbcunit once, then compile the test file with the harness main
cd tests && make -f unit-tests.mk make_fbcunit FBC="$FBC"
cd tests && $FBC -mt -i fbcunit/inc compound/loop.bas fbc-tests.bas -p fbcunit/lib -l fbcunit -x t && ./t
```

Graphics tests open a screen with the null driver, `screenres w, h, bpp, , fb.GFX_NULL`, so they run headless
and can inspect pixels with `point()`. Thread-related tests can rely on `-mt` (see `#ifdef __FB_MT__`) because
the unit tests are built with it everywhere except DOS.

To show that a new test catches a bug, compile the pre-fix version of the one C file from `upstream/master`
and link its `.o` ahead of the library; the object wins over the archive member:

```sh
git show upstream/master:src/gfxlib2/gfx_circle.c > old.c
gcc -DENABLE_MT -Wall -Wextra -Wno-unused-parameter -O2 -I src/gfxlib2 -c old.c -o old.o   # same flags as the makefile
$FBC -mt -i fbcunit/inc gfx/circle-cursor.bas fbc-tests.bas old.o -p fbcunit/lib -l fbcunit -fbgfx -x t && ./t
```

`tests/check-suite-names.sh` is not executable; run it as `bash check-suite-names.sh check`. A full log-test
run leaves untracked test executables behind (e.g. under `tests/cpp/`, `tests/scopes/`); remove them with
`git clean` before committing. New test directories must be added to `tests/dirlist.mk` or they are never
scanned. The generated
`tests/unit-tests.inc` and `tests/log-tests-*.inc` lists are only rebuilt when `dirlist.mk` changes, so after
adding a test file delete the `.inc` (or run `make clean` in `tests/`), otherwise the full run silently skips it.

**Golden-output tests** in `tests/warnings/` and `tests/syntax/` work differently: `./test.sh` (with `FBC`
set) compiles every `.bas` for five targets (dos, linux-x86, linux-x86_64, win32, win64) and writes fbc's
messages to `r/<target>/*.txt`, which are committed. A change is correct when `git diff` is clean after
running the script. Adding a test case here means committing all five `.txt` files. Run these without
`-g -exx`, which perturbs temp-variable names in messages.

## Compiler architecture (`src/compiler/`)

fbc is a single-pass compiler: the parser drives everything and builds an AST per procedure, which is
lowered through the IR to a backend as soon as the procedure ends. There is no whole-program pass.

Driver: `fbc.bas` parses the command line, decides what to compile/assemble/link, and invokes external tools
(as, gcc, ld). For each `.bas` it calls `fbCompile()` in `fb.bas`, which runs `cProgram()`
(`parser-toplevel.bas`) between `irEmitBegin()`/`irEmitEnd()`. Global compiler state is the `env` struct
(`fb.bi`); command-line options live in `env.clopt` and are read via `fbGetOption( FB_COMPOPT_* )`.

Pipeline, front to back:

1. **lex** (`lex*.bas`) — tokenizer with lookahead; also handles `#include` file switching via `fbIncludeFile()`.
2. **pp** (`pp*.bas`) — preprocessor (`#define`/`#macro`, `#if`, `#pragma`), invoked by the lexer.
3. **parser** (`parser-*.bas`) — recursive descent. Files map to grammar areas: `parser-decl-*` declarations,
   `parser-expr-*` expressions, `parser-compound-*` block statements (IF/FOR/WHILE/SELECT/WITH...),
   `parser-quirk-*` the BASIC "quirk" statements (PRINT, OPEN, ON ERROR, PEEK/POKE...), `parser-proccall*`
   calls and argument passing. Compound statements push/pop `FB_CMPSTMTSTK` entries (`parser-compound.bas`).
4. **symb** (`symb*.bas`) — symbol table: scopes, namespaces, procedures, UDTs, overloads, name mangling
   (`symb-mangling.bas`), keywords (`symb-keyword.bas`).
5. **ast** (`ast*.bas`) — one `ASTNODE` class per file (`ast-node-*.bas`); `ast-optimize.bas` does
   constant folding and tree rewrites; `ast-vectorize.bas` the `-vec` SSE vectorizer. Nodes are built with
   `astNew*()` and attached with `astAdd()`; procedures are flushed through `astProcEnd()`.
6. **rtl** (`rtl*.bas`) — tables of `FB_RTL_PROCDEF` describing every runtime-library function the compiler
   may call (`fb_*` symbols implemented in `src/rtlib`). Quirk statements are lowered to calls via these
   tables; the `fb_*` names in `rtl.bi` must match the C side exactly.
7. **ir** (`ir*.bas`) — the AST is lowered through an `IR_VTBL` chosen in `irInit()` by `-gen`:
   `ir-tac.bas` (three-address code → `emit*.bas` x86 asm; `gas`, the default only for 32-bit x86),
   `ir-hlc.bas` (C source compiled by `gcc`/`clang`; the default for every other target, including
   x86_64), `ir-gas64.bas` (direct x86-64 asm, opt-in via `-gen gas64`), `ir-llvm.bas` (LLVM IR).
8. **emit** (`emit*.bas`, `reg.bas`) — x86 register allocation and instruction emission for the TAC backend
   only; the other backends write text directly.

Error handling: `error.bi` holds the `FB_ERRMSG_*` enum and `error.bas` a parallel string table in the
same order. Adding an error means appending to both. Tokens are `FB_TK_*` in `fbint.bi` plus a row in the
keyword table in `symb-keyword.bas`; keywords can be dialect-restricted (`KWD_OPTION_NO_QB`, `QB_ONLY`).

Dialects (`-lang fb|fblite|qb|deprecated`) are pervasive: `fbGetOption( FB_COMPOPT_LANG )` and
`env.clopt.lang` checks appear throughout the parser, and a `#lang` directive can trigger a compiler
restart (`fbShouldRestart()`), so parse-time state must be re-initializable.

A worked example: the recent `END WHILE` addition touched `parser-compound-while.bas` (accept the new
terminator), `parser-compound.bas` (statement dispatch and error recovery), `error.bi`/`error.bas`
(message text), `changelog.txt`, plus tests in `tests/compound/` and `tests/warnings/` with all five
`r/<target>` golden files.

## Runtime library architecture (`src/rtlib/`, `src/gfxlib2/`)

One C function per file, named after the exported `fb_*` symbol (e.g. `array_redim.c` → `fb_ArrayRedim`).
The build compiles everything in `src/rtlib/`, then `src/rtlib/$(TARGET_OS)/` and `src/rtlib/$(TARGET_ARCH)/`,
so platform code is selected purely by directory (`unix/` is shared by linux, the BSDs, darwin, etc.;
`static/` holds the `fbrt0.c` startup object). Each library is also built as `-DENABLE_MT` (thread-safe,
`libfbmt`) and `-fPIC` variants from the same sources. Internal headers are `fb.h`/`fb_private_*.h`;
anything a compiled FB program links against must keep its ABI stable across both variants.

## Conventions

- Indentation is tabs in both `.bas` and `.c` sources. `contrib/tools/check-whitespace.bas` is the
  upstream normalizer (removes trailing whitespace, converts leading spaces to tabs).
- fbc code style: `dim as T ptr x = any`, `'' ` double-apostrophe comments, procedure prefixes by module
  (`c*` parser, `ast*`, `symb*`, `rtl*`, `ir*`, `emit*`, `lex*`, `pp*`, `h*` for private helpers,
  `fb*` for global compiler state).
- User-visible changes get a line in `changelog.txt` under the current version's `[changed]`, `[added]`,
  or `[fixed]` section, in the existing style: `- github #NNN: component: description` when it closes an
  issue (`sf.net #NNN` for the old tracker), otherwise `- component: description`. Append to the end of the
  section. Upstream maintainers expect this in a PR.
- A todo.txt item that a change completes is removed in the same commit.
- Upstream has no CI on GitHub; the lead maintainer builds PRs locally and merges in batches, often weeks
  apart. State in the PR body exactly what was built and run, and say plainly when a platform (win32, DOS)
  could not be built here.
- Commit subjects upstream are prefixed by component (`fbc:`, `gas64:`, `rtlib:`, `gfxlib2:`, `tests:`,
  `fbdocs:`).
- Prefer adding a test for any compiler behavior change: fbcunit for runtime behavior, a `COMPILE_ONLY_*`
  log test for accept/reject rules, and `tests/warnings/` for diagnostics text.
- `todo.txt` is upstream's list of known gaps and design notes; check it before proposing a feature.
